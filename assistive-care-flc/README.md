# Fuzzy Logic Controller for an Assistive-Care Flat

**ST7085CEM Advanced Machine Learning — Task 2 (Evolutionary and Fuzzy Systems)**

A Mamdani fuzzy logic controller for one room of an assistive-care flat, a genetic
algorithm that tunes its membership functions, and a comparison of GA, PSO and
simulated annealing on two CEC'2005 benchmark functions.

Everything here is reproducible from a clean checkout. No results are quoted in the
report that are not regenerated by one of the three scripts below.

---

## Quick start

```bash
python -m venv acflc-venv
acflc-venv\Scripts\activate          # Windows
pip install -r requirements.txt

python scripts/run_part1.py          # controller, audit, figures 1-10   (~30 s)
python scripts/run_part2.py          # GA tuning + control, figures 11-13 (~25 min)
python scripts/run_part3.py          # 180 benchmark runs, figure 14      (~5 min)

pytest                               # 29 tests
```

## The controller at a glance

Mamdani: AND = min, implication = min (clipping), aggregation = max,
defuzzification = centroid.

| | variable | universe | fuzzy sets |
|---|---|---|---|
| in | `room_temp` | 14–34 °C | Cold, Cool, Comfortable, Warm, Hot |
| in | `activity` | 0–10 index | Resting, Light, Active |
| in | `daylight` | 0–100 % design lux | Dark, Dim, Bright |
| in | `preference` | −5…+5 | Cooler, Neutral, Warmer |
| out | `hvac` | −100…+100 % capacity | CoolHigh, CoolLow, Off, HeatLow, HeatHigh |
| out | `dimmer` | 0–100 % | Off, Low, Medium, High |

**54 rules** — 45 thermal (`room_temp × activity × preference`) and 9 lighting
(`daylight × activity`), generated from additive FAM tables rather than written out
one at a time, so a carer can audit three small tables instead of a 54-row list.

**81 tunable membership-function parameters → 648-bit chromosome** at 8 bits/gene.

## Three things worth knowing before reading the results

**1. The Part 2 dataset is synthetic, and that is declared everywhere.**
No public dataset of assistive-care environmental preferences exists, and collecting
one needs ethical approval and residents. The training examples are generated from an
explicitly stated analytical reference policy plus Gaussian noise
([`dataset.py`](src/acflc/dataset.py)). The GA's measured improvement means *the
search can recover a known target*, **not** *the tuned controller is better for real
residents*. The reference policy is deliberately a different functional form from the
controller, so the error cannot be driven to zero by construction.

**2. The Part 3 shift vectors are generated locally, so the numbers are not
comparable with published CEC'2005 results.** The official suite ships the shift
vectors as data files that were not available; the vectors used here are generated
from a fixed seed and written out in full to `results/part3_shift_vectors.json`.
Everything claimed is a *within-study* comparison across three algorithms on identical
instances. No comparison against the literature is made, because it would be unsound.

**3. The Mamdani engine is hand-written and cross-checked against scikit-fuzzy.**
`scikit-fuzzy` is a **test-only** dependency and is never imported by anything under
`src/`. The engine was written rather than imported because Part 2's GA rebuilds the
FIS thousands of times (too slow through `ControlSystem`) and because Part 1 is marked
on rule activation and aggregation, which a library that returns only the defuzzified
scalar hides. `tests/test_against_skfuzzy.py` requires the two to agree on every
consequent activation to 1e-12, and to converge on the crisp output as the output
universe is refined.

## Findings that came out of the analysis rather than the plan

- **A design bug in the first rule base, caught by the audit.** Activity and preference
  each shifted thermal demand a full step, so together they could *overrule* the
  temperature reading: a Comfortable 22.5 °C room with a resting occupant who preferred
  warmth commanded `HeatHigh`. The combined modifier is now clamped to one step, which
  makes "never heat a hot room, never cool a cold one" true by construction. Pinned by
  `test_never_heats_a_hot_room_or_cools_a_cold_one`.

- **The controller cannot reach full actuator authority.** Centroid defuzzification
  spans only [−79.9, +79.9] of the ±100 % HVAC universe, because the aggregated set
  always keeps area on the interior side. Measured against bisector (81.2 %) and
  mean-of-maximum (90.0 %) in `run_part1.py`. A real limit, not a plotting artefact.

- **The HVAC response is not pointwise monotone in temperature**, by about 0.6 % of the
  output span. Where the demand scale saturates, two adjacent temperature sets share a
  consequent and its activation is V-shaped through their crossover. Bounded, declared,
  and an order of magnitude below any real actuator's resolution.

- **Part 2 includes a budget-matched random-search control.** A GA that improves on its
  starting point has not shown that *evolution* did the work — a finer random sample
  might do the same. See `results/part2_ga.json` for the verdict.

## Test suite

```
tests/test_controller.py        behavioural properties the report claims

tests/test_parts_2_and_3.py     GA encoding, budget enforcement, benchmark optima
```

Each test pins a specific claim, so an edit to the membership functions or the rule
base cannot quietly falsify a sentence in the write-up.
